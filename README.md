# Видео — Скачать

Расширение Chrome с собственным логотипом, кнопками у видеокарточек и окном управления текущим роликом. Общий режим подключается к HTTP/HTTPS-страницам и ищет стандартную видеоразметку, ссылки видеокарточек, HTML5 video и OpenGraph Video. Он не ограничен списком Яндекс/VK/ОК/Mail.

## Установка на macOS

Нужен Python 3. Запустите `install.command`: он установит yt-dlp из PyPI в изолированное окружение `~/Library/Application Support/YandexVideoDownloader` и зарегистрирует помощника только для ID этого расширения. Если ffmpeg/Node уже установлены, помощник использует их; автоматически они не устанавливаются.

В `chrome://extensions` включите режим разработчика, нажмите «Загрузить распакованное расширение» и выберите корень репозитория. После обновления файлов обновите карточку расширения, подтвердите запрошенный Chrome доступ к сайтам и перезагрузите страницы с видео.

## Как пользоваться

У видеокарточек появляются компактные кнопки ↓. Кнопка скачивает именно ролик своей карточки. В окне расширения доступно скачивание/отмена текущего ролика; если стандартный плеер не распознан, можно вручную нажать «Найти видео на странице». Страницы-плейлисты не скачиваются целиком — нужно выбрать карточку. Также доступны статус помощника, папка с видео и полезные ссылки. Файлы: `Загрузки/Яндекс Видео`. До двух загрузок одновременно; закрытие вкладки отменяет её загрузки. Повтор после ошибки — только вручную.

В «Настройки кнопок» выбирается размещение: четыре угла превью или отдельно рядом с карточкой. Плавающая панель текущего ролика на странице выключена по умолчанию, но её можно включить. Настройки сохраняются локально и применяются к открытым страницам.

## Границы возможностей

Наличие видео на экране не гарантирует доступный файл. Скрытые blob/MSE-потоки, canvas, закрытые shadow DOM, нестандартные карточки и защищённые плееры могут не определяться или не скачиваться. Закрытые, DRM-защищённые, требующие входа и заблокированные источником ролики не обходятся. Для неизвестного сайта используется общий механизм yt-dlp. Пользовательские cookies и пароли не читаются и не передаются. Доступность каждой конкретной площадки меняется независимо от расширения.

Для общего режима Chrome запрашивает доступ к данным HTTP/HTTPS-сайтов: это нужно для размещения кнопок и чтения источника выбранного видео. Код не считывает формы, пароли или переписку; нет разрешений history/cookies/tabs, серверной аналитики и фоновых автоматических загрузок. Только после нажатия выбранная публичная ссылка передаётся локальному помощнику. Внутренние/локальные IP-адреса и file URLs запрещены. Сетевой guard проверяет адреса Python-соединений, в том числе при редиректах. Локальный HTTP-прокси также может быть отклонён этим guard. Внешний ffmpeg используется для обработки уже скачанных файлов, а не сетевого скачивания.

## Проверки

`node --test tests/players.test.cjs`

Проверяются границы источников текущего плеера и карточек, общий DOM без привязки к сайту, настройки, popup, native origin/команды, запрет непубличных адресов и PNG-иконки. Синтетические проверки не доказывают работу каждого сайта.

## Удаление

Удалите расширение в Chrome. Затем удалите только его регистрацию `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/ru.local.yandex_video_downloader.json`, если она указывает на `YandexVideoDownloader/native/launch.command`, и папку `~/Library/Application Support/YandexVideoDownloader`. Скачанные видео останутся в Загрузках.

Контролы размещены в собственном изолированном Shadow DOM-слое поверх превью. Разметка карточек сайта не переписывается. Сканируются видимые карточки; прокрутка и подгрузка обновляют слой с ограниченной частотой.

### Обновление 2.0.2

Кнопки очищаются при переходах внутри сайта и скрываются, если карточку перекрывает плеер. Кнопка от предыдущего адреса не запускает скачивание. Явные ссылки на оригинал в карточках Яндекс Видео принимаются независимо от домена и формы пути — включая старые адреса Mail.ru. Поддержка загрузки файла по найденному адресу зависит от доступности источника и возможностей загрузчика.

### Обновление 2.1.0

В окне расширения можно выбрать качество следующих загрузок: лучшее доступное (по умолчанию), до 1080p, 720p, 480p или 360p. Выбор сохраняется и действует на карточки и текущее видео. В пределах выбранного ограничения скачивается лучший доступный вариант, без перехода к более высокому разрешению. Если подходящего формата нет, загрузчик сообщит об ошибке. При установленном FFmpeg отдельные видео и звук объединяются. Разрешение добавляется в имя файла, чтобы ранее сохранённый вариант меньшего качества не подменял новый. Искусственный предел размера 4 ГиБ снят.

Проверка обновлений обращается только к публичному manifest.json этого репозитория на raw.githubusercontent.com: при запуске фонового обработчика, открытии окна и затем раз в 6 часов (результат кэшируется). Доступны ручная проверка и кнопка скачивания ZIP из этого репозитория. При ошибке сети сохраняется последняя известная версия с пометкой ошибки. Код из сети не исполняется и не устанавливается автоматически.

После скачивания распакуйте ZIP, замените файлы в папке установленного расширения и нажмите «Обновить» на его карточке в Chrome; обновите видеовкладки. При изменениях native-помощника запустите install.command из нового архива. Для 2.1.0 помощник требуется обновить. Новые разрешения: alarms для периодической проверки и raw.githubusercontent.com для чтения версии; Chrome может запросить подтверждение доступа.

### Windows и Яндекс Браузер (2.2.0)

Одного расширения недостаточно: локальный помощник нужен на **каждом компьютере**. Скачайте и распакуйте архив, установите Python 3.10+ с python.org (если его нет), затем запустите `install-windows.cmd`. Он создаёт отдельное окружение в `%LOCALAPPDATA%\YandexVideoDownloader`, устанавливает yt-dlp, Send2Trash и FFmpeg через пакет imageio-ffmpeg из PyPI и регистрирует помощник для текущего пользователя в Chrome и Яндекс Браузере. Права администратора и изменение политик браузера не нужны. В окне расширения нажмите «Проверить связь». Расширение и помощник должны использовать один ID из extension-id.txt. Установщик отказывается заменять чужую регистрацию. Работа на macOS не доказывает установку на Windows.

В окне расширения появился список последних 100 загрузок. «Остановить» отменяет загрузку и её дочерние процессы; неполный файл может остаться для продолжения при повторе. «Повторить» использует прежнее выбранное качество. «Убрать из списка» удаляет только запись; «Файл в корзину» переносит завершённый файл в системную корзину и убирает запись. Файлы вне фиксированной папки загрузок и символьные ссылки не удаляются; при ошибке корзины постоянное удаление не применяется. При закрытии видеовкладки скачивание продолжается. История хранится локально, не отправляется на GitHub; после перезапуска незавершённая загрузка отмечается прерванной.

### Исправление Windows 2.2.1

Исправлено зависание на «Соединение…»: дочерний Python-процесс больше не наследует входной канал команд браузера. Загрузчик сразу сообщает о подготовке. Исправление проверено на домашнем Windows: начало прогресса и отмена через native-протокол проходят. Помощник возвращает полный путь сохранённого файла для управления корзиной; путь проверяется внутри фиксированной папки.

### Память скачанных видео (2.2.2)

После успешного сохранения карточка получает зелёную кнопку ✓. Нажатие позволяет скачать ролик ещё раз. Отметки последних1000 успешно скачанных адресов хранятся локально в профиле расширения и восстанавливаются при открытии другой вкладки и перезапуске браузера. Существующие завершённые записи истории тоже учитываются. «Убрать из списка» сохраняет отметку, а успешное действие «Файл в корзину» снимает её. Для этой версии менять native-помощник2.2.1 не требуется.

### Выбор одного ролика (2.2.3)

Исправлен отказ при списке-обёртке с единственным видео: теперь скачивается этот ролик. В списке из нескольких элементов допускается только одно точное совпадение с выбранной ссылкой; автоматически брать первый элемент нельзя. Подготовка ограничена100 элементами и6 уровнями вложенности, циклы отклоняются. Общий дефект проверен на моделях метаданных; без конкретной ссылки стороннего сообщения работа того сайта не считается подтверждённой.

**Это исправление требует обновить помощник**, а не только расширение: из нового архива запустите install-windows.cmd на Windows или install.command на macOS. В окне расширения появится подсказка, если помощник старее2.2.3.

### Рекламные плееры: защита выбора источника (2.2.4)

Запасной способ больше не скачивает currentSrc первого HTML5-плеера: во время рекламы этот адрес может принадлежать рекламному ролику. Вместо него передаётся исходная страница для извлечения основного контента. Общие карточки и встроенные плееры с явной рекламной пометкой исключаются; короткая длительность или незнакомый домен сами по себе не считаются рекламой. Это не универсальный детектор рекламы и не блокировщик. Новых разрешений или изменений помощника по сравнению с2.2.3 нет. Проверено24 локальными регрессиями; конкретная страница с рекламой в этом патче не проверялась.

Основания: [Video.js: режим рекламы и смена src](https://videojs.github.io/videojs-contrib-ads/integrator/api.html), [Google IMA: события рекламы/возврата контента](https://developers.google.com/interactive-media-ads/docs/sdks/html5/client-side/reference/namespace/google.ima.AdEvent), [AWS: реклама может быть встроена в HLS/DASH-манифест](https://docs.aws.amazon.com/mediatailor/latest/ug/what-is-flow.html). Сетевое обнаружение медиапотоков требует отдельного механизма корреляции и доступа [webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest); в этом патче оно не добавлено.

### Параллельные загрузки и действия с файлом (2.2.5)

В окне расширения под качеством можно вручную задать от1 до20 одновременных скачиваний; по умолчанию5. Значение сохраняется локально, действует на все вкладки и повторные попытки и применяется без перезапуска. Уменьшение лимита не отменяет уже запущенные загрузки. При достижении лимита новый запуск отклоняется с объяснением.

У завершённых загрузок появились «Открыть» и «Показать в папке». Первая кнопка открывает файл стандартным приложением, вторая выделяет его в Finder/Проводнике. Помощник принимает только существующие медиафайлы из своей папки загрузок; пути от страницы или указанные вручную в сообщении не используются. Windows выделяет файл через [SHOpenFolderAndSelectItems](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems), без shell-команд со строкой пути. Для этих кнопок требуется помощник2.2.5: повторно выполните install-windows.cmd или install.command из нового архива. Сам лимит загрузок не требует обновления помощника.

### Яндекс Музыка (2.3.0)

Кнопки: слева от строк треков, справа над текущим плеером и «Скачать альбом» рядом с управлением альбомом. Во время загрузки альбомная кнопка становится «Остановить альбом» с общим прогрессом. Альбом читается целиком из метаданных сервиса (до500 треков), независимо от прокрутки/виртуализации списка, и скачивается последовательно в одном слоте общего лимита. Отмена останавливает текущую операцию; уже завершённые файлы сохраняются и отмечаются зелёным. Повторная попытка сохраняет существующие файлы. Завершённые треки альбома также появляются отдельно в истории с действиями «Открыть»/«Показать в папке». Для завершённых отдельных треков доступны прежние действия с файлом в истории; у альбома единого файла нет, используйте «Открыть папку».

Поддерживается лучший из доступных **полных MP3**; настройка разрешения видео на музыку не влияет. Папка пока общая: «Загрузки/Яндекс Видео». Нужен помощник2.3.0: запустите install.command / install-windows.cmd из нового архива. Новых разрешений нет.

**Ограничение:** вход браузера не передаётся помощнику. Публичный API часто выдаёт только превью; такие записи отклоняются с понятным сообщением, а не сохраняются как полные песни. Авторизация/подписка, защищённые потоки и CAPTCHA не обходятся. На альбоме1750287 реальный запрос для трека15608804 вернул только preview; полная загрузка этого примера **не подтверждена и сейчас недоступна через этот режим**. Кнопки и последовательная обработка проверены локальными моделями; это не подтверждение загрузки защищённого каталога.

Использованы публичные методы из первичных исходников [yt-dlp YandexMusic](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/yandexmusic.py) и [yandex-music-api DownloadInfo](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/download_info.py). Без импорта cookies, OAuth или извлечения токенов из браузера.

### Плееры, прокрутка и ожидание рекламы (2.3.1)

Музыкальные кнопки теперь жёлтые с толстой чёрной SVG-стрелкой. Кнопка текущего трека располагается внутри нижнего плеера, у «Моей волны» — внутри области плеера справа. Добавлен поиск единственной видимой ссылки текущего трека в собственной meta-области «Моей волны»; неоднозначный список не подменяет текущую песню. Внутренняя прокрутка перехватывается в capture-фазе, положение обновляется через requestAnimationFrame, переиспользованная строка с другим треком сразу скрывает старую кнопку и отклоняет устаревший клик.

На доступном HTML5-видеоплеере (от240×135) появились «Скачать видео» и «После рекламы». Второе действие ставит одну локальную заявку в ожидание. Автоматический запуск происходит только после наблюдавшейся рекламной отметки плеера (например, Video.js/YouTube), её исчезновения и1,5с воспроизведения с продвижением времени. Если рекламной отметки нет, автоматический запуск не угадывается: после просмотра используйте «Скачать сейчас». Ожидание можно отменить; через5минут оно истекает. Переход на другую страницу, смена исходного ролика или удаление выбранного видео отменяют ожидание. Закрытие страницы не оставляет фоновую заявку.

Скачивается исходная страница ролика через существующий помощник, а не временный src рекламы. Лимит и качество действуют как прежде, качество фиксируется при постановке в ожидание. Это ожидание **не устраняет** ограничения входа, DRM, запрет сервиса, встроенную в поток рекламу или несовместимость загрузчика. Плееры внутри чужого iframe и сайты без доступного признака рекламы не поддерживают автоматическое определение её конца. При замене самого video-элемента сайт должен быть выбран заново. Доступ к браузерным cookies/токенам и новые разрешения не добавлены; помощник2.3.0 менять не нужно.

Основания: [Video.js: ad mode и возврат content playback](https://videojs.github.io/videojs-contrib-ads/integrator/api.html). Один лишь конец media или смена src не считается подтверждением окончания рекламы. Ожидание и прокрутка проверены локальными моделями; живое скачивание после рекламы на конкретном сайте пока не подтверждено.
